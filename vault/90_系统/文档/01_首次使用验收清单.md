# 首次使用验收清单

本文只解决一件事：让一个此前不了解 kos 的用户，从零开始走到“桌面端可工作、iPad 可同步”的可验证状态。每一步都给出完成标准；没有通过时不要跳到下一步。

## 先选择你要的能力

| 设备 | 可用能力 | 额外要求 |
|---|---|---|
| 桌面端 | 驾驶舱、Reader、kos-agent、同步 | Obsidian Desktop、Node.js 22.19+、模型 API key |
| iPad | 驾驶舱、Reader、同步 | Obsidian Mobile；不需要 Node.js 或模型 API key |

iPad 不运行本地 kos-agent。第一次初始化应先在桌面端完成，再让 iPad 加入同一个同步 Vault。只有 iPad 的用户目前不能获得完整 Agent 能力。

## 0. 准备

准备以下内容：

- Obsidian Desktop 1.5 或更高版本；
- Node.js 22.19 或更高版本；
- 一个支持的模型 provider、model ID 和 API key；
- 如需多端同步，再准备私人 Cloudflare R2 Bucket 及限定到该 Bucket 的 Object Read & Write 凭据。

多端同步不是首次启动的前置条件。先让桌面端独立可用，再配置 R2。

## 1. 得到一个可打开的 kos Vault

如果 GitHub Releases 页面中确实存在 `kos-vault-<version>.zip`，下载并解压它，用 Obsidian 打开其中的 `kos-user-vault` 文件夹。不要把 GitHub 自动生成的 Source code ZIP 当成 kos Vault 发布包。

如果 Releases 页面还没有上述文件，说明公开发行尚未完成。当前只能使用维护者提供的已校验发布包，或从源码安装：

```bash
git clone https://github.com/Asong6824/kos-framework.git
cd kos-framework
node dev/harness/install_local.mjs "/path/to/my-kos-vault"
```

不要把个人笔记写入源码仓库的 `vault/`。安装目标必须是另一个空目录，或者已经包含 `.kos.md` 的 kos Vault。

完成标准：

- Vault 根目录直接包含 `.kos.md`、`00_工作台`、`10_收件箱`、`80_Skills` 和 `90_系统`；
- `.obsidian/plugins/kos-companion/` 内直接包含 `manifest.json`、`main.js`、`styles.css` 和桌面端 `kos-agent/`；
- 目录中没有再套一层 `kos-user-vault/kos-user-vault` 或 `kos-companion/kos-companion`。

## 2. 第一次打开 Obsidian

1. 在 Obsidian 选择“打开本地文件夹作为仓库”，选择上一步的 Vault 根目录。
2. 进入“设置 → 第三方插件”，关闭 Restricted Mode。
3. 手动启用 kos Companion。
4. 插件会为全新安装自动打开“首次使用 kos”向导。按向导检查；关闭后可从命令面板或“设置 → kos Companion → 首次使用向导”重新打开。
5. 点击左侧仪表图标打开 kos 驾驶舱，再点击消息图标打开右侧 kos Agent。

完成标准：驾驶舱能打开；右侧能看到 kos Agent 首次启动卡。插件文件存在但没有入口时，先检查目录是否多套一层，再彻底重启 Obsidian。

## 3. 配置桌面 Agent

1. 在首次启动卡点击“配置模型”。
2. 填写 provider、model ID 和 API key。只有使用自定义中转时才填写 Base URL 和 API 协议。
3. 点击“保存并测试”，确认模型真实请求成功后再运行系统检查。

使用火山引擎 Coding Plan 时点击“火山 Coding Plan”预设，再填写套餐 API key。预设使用 `ark-code-latest`、专用地址 `https://ark.cn-beijing.volces.com/api/coding/v3` 和 OpenAI Completions 协议。不要改用普通方舟推理地址 `/api/v3`，以免产生套餐外费用。

API key 保存在 kos-agent 的本机配置目录，不应写入 Markdown、截图或 Issue。kos-agent 只有 YOLO 模式，可以在 Obsidian 进程已有权限范围内读写文件和执行命令，但涉及目标和人工审阅结论时仍应等待你的判断。

完成标准：先出现“模型连接成功”并显示耗时；模型配置后输入框可用；系统检查显示：

```text
Harness: PASS
Errors: 0
Warnings: 0
```

如果 Agent 无法连接，先查看 [[90_故障排查]]，不要通过复制源码目录或降低 Node 版本绕过。

## 4. 建立第一组真实内容

空 Vault 里没有 Goal、Project 或 Task，因此不要直接要求 kos“安排今天”。点击首次启动卡中的“填写第一个工作流”，让 Agent 先询问你的半年重点、当前事项和今天可用时间，并提出最小初始化方案。

确认方案后，至少应产生：

- `30_目标/` 中一个 Goal；
- `31_项目/` 中一个 Project；
- `32_任务/` 中一个可执行 Task。

然后再使用“开始一天”。

完成标准：驾驶舱“行动”区能看到新对象；Agent 明确告诉你修改了哪些文件；再次运行系统检查仍然通过。

## 5. 可选：启用 R2 多端同步

按 [[65_多端同步]] 完成第一台设备配置。设置中只填写 Account ID、Bucket、Access Key ID 和 Secret Access Key；Cloudflare 的 Token value 和完整 endpoint 都不填。填写后先点击“测试 R2 读写”，通过后才启用同步。测试对象位于隔离前缀，验证后自动删除，不会改写 Journal。

完成标准：桌面驾驶舱“系统 → 多端同步”显示“已同步”，最后同步时间是当前时间，待上传和待应用最终归零。未达到这个状态前不要生成加入码，也不要开始配置 iPad。

## 6. 可选：让 iPad 加入

当前普通用户能否独立安装，取决于 kos Companion 是否已经进入 Obsidian 社区插件渠道。社区渠道尚未提供时，`kos-companion-mobile-<version>.zip` 只是测试发行物，不能把写入 iPad 隐藏插件目录描述成零门槛流程。

插件已经正确安装后：

1. 在 iPad 的“在我的 iPad 上”创建一个空 Obsidian Vault，不要放在 iCloud Drive。
2. 启用 kos Companion。
3. 在桌面端点击“复制本机加入码”。
4. 在 iPad 点击“从剪贴板加入”，完整粘贴以 `KOS-SYNC1.` 开头的一整行加入码。
5. 导入成功后清空两端剪贴板，把 Obsidian 保持在前台直到同步完成。

完成标准：iPad 显示“已同步”，最后同步时间更新，桌面端的 Goal、Project、Task 以及 `00–90` 目录结构均出现。只有少数目录或仍停留在旧文件数时，按 [[66_多端同步故障排查]] 处理。

## 7. 首次使用完成

同时满足以下条件才算完成：

- 桌面驾驶舱和 Agent 都能打开；
- 模型调用成功，系统检查无错误；
- 至少有一个 Goal、Project 和 Task；
- 如启用同步，两端最后同步时间均已更新，且能在一端新建测试笔记后在另一端看到；
- 用户知道 iPad 没有本地 Agent、R2 不是备份、加入码包含未加密凭据；
- Vault 没有同时启用第二套双向同步。

完成后继续阅读 [[00_快速开始]]，按日常规划、输入处理、阅读和研究流程逐步扩展。不要在第一天一次性配置全部目录映射、Skill 或集成。
