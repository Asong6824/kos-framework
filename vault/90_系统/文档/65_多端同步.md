# 多端同步

kos Companion 内置 kos-sync，通过私人 Cloudflare R2 在桌面、iPad 和其他 Obsidian 设备之间同步 Vault，不需要再安装 Self-hosted LiveSync。

如果这是第一次使用 kos，先完成 [[01_首次使用验收清单]] 的桌面安装、Agent 配置和第一组对象创建。R2 不是初始化 kos 的前置条件；源端尚未验证时不要开始配置 iPad。

## 安全边界

- 第一版只支持私人 Cloudflare R2、单人多设备。
- 同步内容**不做端到端加密**。能够读取 Bucket 的人可以直接读取其中的数据。
- Bucket 必须保持私有；R2 凭据只授予该 Bucket 的 Object Read & Write 权限。
- 同一个 Vault 启用 kos-sync 后，不要再同时启用 iCloud、Obsidian Sync、Syncthing、Git 自动双向同步或其他同步插件。
- `.obsidian/`、`.git/`、`.kos.md`、`.hermes.md`、Framework 备份、kos-agent Session 和本机凭据不会进入 kos-sync。

## 1. 在 Cloudflare 创建 R2

1. 在 Cloudflare R2 中创建一个私有 Bucket。
2. 创建只作用于该 Bucket 的 R2 API Token，权限选择 Object Read & Write。
3. 保存以下四项：
   - Cloudflare Account ID
   - Bucket 名称
   - Access Key ID
   - Secret Access Key

Cloudflare 页面同时显示的 **Token value 不需要填入 kos**。kos 使用 S3 兼容的 Access Key ID 和 Secret Access Key。插件会根据 Account ID 自动生成 R2 endpoint，不要把完整 endpoint 填进 Account ID。

## 2. 配置第一台设备

1. 用 Obsidian 打开已经初始化的 kos Vault。
2. 进入“设置 → 第三方插件”，关闭 Restricted Mode，并手动启用 kos Companion。
3. 打开“设置 → kos Companion → 多端同步”。
4. 依次填写 Account ID、Bucket、Access Key ID 和 Secret Access Key。
5. 点击“测试 R2 读写”。插件会检查 Bucket、列出当前同步前缀，并写入、读回、删除一个随机隔离测试对象。
6. 测试通过后打开“多端同步”开关。
7. 打开 kos 驾驶舱，在“系统 → 多端同步”中确认状态变为“已同步”。

第一次测试会为这个同步空间生成稳定 Vault ID；第一次启用会把当前 Vault 上传到 R2。测试成功只保存配置指纹和时间，不保存第二份明文凭据。Account ID、Bucket、Access Key、Secret 或 Vault ID 变化后必须重新测试。不要在字段尚未填完时提前打开同步开关。

## 3. 加入第二台设备

第二台设备可以是桌面 Obsidian，也可以是 iPad。iPad 只运行看板、Reader 和同步，不运行本地 kos-agent，也不需要 Node.js。

1. 在第二台设备创建一个本地 Obsidian Vault。
2. 安装并启用 kos Companion。iPad 使用发布归档 `kos-companion-mobile-<version>.zip`，解压后的 `manifest.json`、`main.js` 和 `styles.css` 必须直接位于 `.obsidian/plugins/kos-companion/`；正式用户优先使用 Obsidian 社区插件渠道。
3. 在第一台设备的 kos Companion 设置中点击“复制本机加入码”。
4. 在第二台设备点击“从剪贴板加入”。
5. 如果系统不允许插件读取剪贴板，在弹出的输入框中手动粘贴加入码，然后点击“加入并开始同步”。
6. 导入成功后立即清空剪贴板。
7. 在驾驶舱确认状态为“已同步”，并检查 Runtime 文档和个人文件均已出现。

遇到“加入码不完整”、目录不全、状态长期不变或移动端加载失败时，按
[[66_多端同步故障排查]] 逐项检查，不要删除 checkpoint、清空 Bucket 或改装第二个同步插件。

加入码包含未加密的 R2 凭据。它不是短时失效的一次性密码：在你轮换 R2 凭据前，拿到加入码的人仍可能访问 Bucket，所以只能在可信设备之间临时传递。

如果第二台设备已经包含相同的 kos Runtime，kos-sync 会先接收远端并按内容去重；本地独有文件会在随后上传，内容不同的同名文件会保留为冲突副本，不应直接覆盖或删除。

## 4. 日常使用

kos-sync 会在以下时机自动运行：

- Obsidian 启动；
- 文件创建、保存、删除或重命名；
- 打开文件；
- 网络恢复；
- Obsidian 窗口重新获得焦点或从后台回到前台；
- 前台运行期间每 45 秒检查一次。

iPadOS 挂起 Obsidian 后不承诺后台同步。重新打开 Obsidian 后，kos-sync 会读取 checkpoint 并追平。需要立即确认时，在驾驶舱点击“立即双向同步”；该按钮会在同一轮中上传本机变化、拉取远端变化并应用到 Vault，不是单向覆盖操作。

驾驶舱会显示最后尝试、最后成功、上次耗时、待上传、待应用、冲突数、R2 读写测试状态和当前错误。待上传/待应用是当前同步轮次尚未处理的 Vault 变更数，不是 R2 Object 或 chunk 数量；完成后应归零。“最后成功”只代表当前设备完成了双向检查，不代表另一台离线设备已经追平。正常使用不需要处理 LiveSync 的 Journal、chunk、checkpoint 或同步模式选项。

## 5. 冲突与恢复

- 两端内容相同：自动去重。
- 两端同时修改且内容不同：保留 `.sync-conflict-*` 副本，由你比较后删除不需要的版本。
- 一端删除、另一端同时编辑：主路径遵循删除，同时把编辑内容保留为冲突副本。
- checkpoint 损坏：原文件会先改名隔离，再重建状态；无法隔离时同步停止，不覆盖原状态。
- 导入另一个 Vault 的加入码：本地 checkpoint 会按 Vault ID 隔离，不能沿用上一个同步空间的删除历史。

远端清空、指定设备覆盖其他设备、批量删除冲突副本都属于灾难恢复操作，kos 不会自动替你选择真相源。

## 6. 常见问题

完整症状与恢复步骤见 [[66_多端同步故障排查]]。下面只保留最常见的入口问题。

### 一直显示“同步错误”

依次检查 Account ID、Bucket、Access Key ID、Secret Access Key，以及 Token 是否确实拥有该 Bucket 的 Object Read & Write 权限。不要把 R2 endpoint 或 Token value 填错字段。

### iPad 没有自动更新

先把 Obsidian 切回前台，打开驾驶舱并点击“立即双向同步”。如果仍失败，使用“重试同步”或打开同步设置检查 R2 读写测试；不要改用第二个同步引擎绕过。

### “从剪贴板加入”弹出输入框

这是移动系统或 Obsidian 拒绝剪贴板读取时的正常回退。回到第一台设备点击“复制本机加入码”，再粘贴完整的 `KOS-SYNC1.` 加入码。不要从聊天气泡分段选择；窗口会显示实际粘贴的字符数。

### 如何停用

关闭 kos Companion 设置中的“多端同步”。这只停止当前设备，不会自动删除 Bucket 数据，也不会关闭其他设备。凭据泄露时应在 Cloudflare 轮换或撤销 R2 Token。
