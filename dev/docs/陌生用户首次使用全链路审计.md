# 陌生用户首次使用全链路审计

日期：2026-07-31

## 审计目标

目标用户此前不了解 kos，不会区分 Framework、Vault、Companion、Agent、R2 或 Obsidian 的桌面/移动能力。验收终点不是“构建成功”，而是用户能独立回答：从哪里下载、打开哪个目录、如何确认插件和 Agent 可用、空 Vault 先做什么、何时配置同步、iPad 上有哪些能力，以及失败时去哪里排查。

## 用户漏斗

```text
获得可信发行物
  → 打开正确的 Vault 根目录
  → 启用 kos Companion
  → 桌面 Agent 连接并配置模型
  → Harness 通过
  → 建立首个 Goal / Project / Task
  → 第一台设备完成 R2 首次上传
  → iPad 安装移动插件并用加入码加入
  → 双端文件往返验证
```

任何上游步骤未通过，都不应靠继续配置下游步骤来掩盖。

## 本轮发现与处理

| 阶段 | 陌生用户看到的问题 | 处理 |
|---|---|---|
| 下载 | 文档直接指向 GitHub Releases，但当前仓库没有已发布 Release | 文档改为只有看到版本化资产才使用；明确 Source code ZIP 不是 Vault；源码安装作为当前可执行入口 |
| 发布 | CI 已构建移动包，但 tag 发布命令没有上传移动 ZIP | GitHub Release 资产加入 `kos-companion-mobile-<version>.zip`，普通 CI 同时上传移动构建 artifact |
| 插件元数据 | manifest 的作者链接与真实远端仓库不一致 | 修正为 `Asong6824/kos-framework` |
| 首次 Agent | 空 Vault 的按钮直接生成“读取 Goal/Project 并开始一天”，没有数据可读 | 改为先询问用户重点并提出最小初始化方案，确认后创建首个 Goal、Project、Task |
| 模型配置 | 保存配置不代表 API key、model ID、协议和地址真的可用 | 增加不进入 Session 的连接测试、脱敏错误分类和火山 Coding Plan 专用预设 |
| 首次路径 | 启用插件后仍要从多个入口寻找模型、检查、初始化与同步 | 新安装自动打开可恢复向导；桌面和移动端使用不同完成标准，命令与设置均可重开 |
| R2 配置 | 填写凭据后直接启用，错误只能等同步引擎启动后暴露 | 首次启用与配置变化强制隔离读写预检，按错误类别提示并记录非明文配置指纹 |
| 同步设置 | 第一台设备和加入设备共用同一设置区，新用户可能在 iPad 再填四个字段 | 设置页明确区分“第一台设备填写字段”和“第二台设备使用加入码” |
| 同步反馈 | 加入码保存后，即使首次同步未完成也固定提示“已加入” | 根据真实同步 snapshot 区分“已同步”和“配置已保存但尚未完成” |
| 同步状态卡 | “待应用”实际递增已应用数；恢复后可能用“已同步”覆盖冲突；首次连接失败无法从卡片真正重试 | 改为剩余数并在成功后归零；恢复按最终冲突定相位；错误时重新初始化；增加最后尝试、耗时、R2 预检与双向同步/设置入口 |
| 发布完整性 | Vault ZIP 只检查快速开始文档，不能保证同步和首次验收文档随包发布 | 发布归档校验新增首次使用清单、同步指南和同步排障文档 |
| 用户文档 | 快速开始同时介绍大量功能，没有从零完成标准 | 新增 Runtime 文档 `01_首次使用验收清单.md`，每一步提供完成标准和停止条件 |

## 此前真机流程已暴露并修复的问题

- 移动 bundle 残留 Node `events` 外部依赖，导致 iPad 插件加载失败。
- Obsidian 可见文件 API 漏掉 `.gitkeep`，导致同步后空目录消失。
- 新 Obsidian profile 的 IndexedDB 为空，但旧 checkpoint 让源端误报已同步。
- 加入码经过聊天复制被截断，错误提示无法说明根因。
- R2 分页读取和远端首次恢复需要保持完整，不得以减少同步内容降级处理。

对应用户排障统一记录在 Runtime 的 `66_多端同步故障排查.md`。

## 仍未完成的发布级阻塞

### P0：尚无公开 GitHub Release

CI 和本地脚本能生成三类 ZIP，但没有版本 tag 就不会产生普通用户可下载的 Release。首次公开测试前必须完成版本号、tag、release notes、三类资产和 `SHA256SUMS` 的一致性验收。

### P0：iPad 尚无普通用户安装渠道

移动 ZIP 已可运行，但 Obsidian Mobile 不能从设置页直接导入任意插件 ZIP。进入 Obsidian Community Plugins 或建立明确受支持的测试分发渠道前，不能宣称陌生用户可以独立完成 iPad 安装。USB 写入隐藏目录只属于真机开发验收。

### P1：发行前仍需补齐的场景验收

- 两端离线修改同一路径后的冲突处理；
- R2 Token 撤销、轮换后两端提示和恢复；
- 大附件、中文长路径、删除与重命名；
- iPad 前后台切换与强制退出后的追平；
- 连续使用和 R2 请求量/成本观察；
- 从公开 Release 下载后的干净机器安装，而不是从工作区 `release/` 目录安装。

## 发布门槛

面向陌生用户宣布“可从零使用”前，应同时满足：

1. GitHub Release 真实存在，包含完整 Vault、桌面插件、移动插件和 SHA256。
2. 全新桌面机器不依赖源码仓库完成安装、模型配置、Harness 和首个对象创建。
3. iPad 有普通用户可执行的插件安装渠道。
4. 桌面与 iPad 完成新建、修改、重命名、删除、冲突、离线恢复和凭据撤销验收。
5. 所有公开入口只指向同一份首次使用清单，且不会把移动端描述为具有本地 Agent。
